# Reference-pack backend facts

Gathered for [How are Reference packs built and distributed?](https://github.com/ailabhq/model-fitter/issues/17), 2026-11-24. `[INFERENCE]` marks conclusions no source states directly.

Tinker answers below come from its docs as generated from SDK 0.40.0 at commit [`3e952a8`](https://github.com/thinking-machines-lab/tinker/tree/3e952a8b979654cacc9dc68aadeb50bc418036a7). Source code links are pinned to the commits named in each section.

## 1. Tinker limits
- **Maximum `topk_prompt_logprobs` k:** not documented as a number. The SDK docstring only says "the server bounds" cost as `len(prompt) * k`, "the way it bounds a top-k width" ([sampling_client.py L505-530](https://github.com/thinking-machines-lab/tinker/blob/3e952a8b979654cacc9dc68aadeb50bc418036a7/src/tinker/lib/public_interfaces/sampling_client.py#L489)). So at fixed k, a longer prompt is more likely to hit that bound. [INFERENCE] Whether k=20 on 8K tokens (about 160K cells) fits has to be tested.
- **Prompt length:** context is 64K/256K for Qwen3.8-27B. Inkling 2 Mini samples "up to 1M tokens" ([Models & Pricing](https://tinker-docs.thinkingmachines.ai/tinker/models/models_and_pricing/index.md)). `SupportedModel.max_context_length` reports the limit per model ([type](https://tinker-docs.thinkingmachines.ai/tinker/api-reference/types/supportedmodel/index.md)). An 8K sequence is within context. The only open question is the top-k cost bound above.
- **Rate and batch limits:** no published numbers. The server sets in-flight sampling concurrency (`sample_max_concurrent_requests`, [ClientConfigResponse](https://github.com/thinking-machines-lab/tinker/blob/3e952a8b979654cacc9dc68aadeb50bc418036a7/src/tinker/types/client_config_response.py#L39)). There is a dispatch rate limiter by bytes ([sampling_client.py L405](https://github.com/thinking-machines-lab/tinker/blob/3e952a8b979654cacc9dc68aadeb50bc418036a7/src/tinker/lib/public_interfaces/sampling_client.py#L405)) and HTTP 429 `RateLimitError` ([docs](https://tinker-docs.thinkingmachines.ai/tinker/api-reference/exceptions/ratelimiterror/index.md)). Tinker is "optimized for throughput rather than latency" ([under the hood](https://tinker-docs.thinkingmachin…
- **Cost of 24K tokens:** about $0.004 for Inkling and $0.017 for Qwen at the listed prefill prices ([pricing](https://tinker-docs.thinkingmachines.ai/tinker/models/models_and_pricing/index.md)). [INFERENCE]

## 2. Tinker serving precision
- Not documented for either model on the SDK sampling path. The only precision tag anywhere is on the serverless IDs `Inkling…:sampling-nvfp4` and `Inkling-Small…:sampling-nvfp4`. Inkling-2-Mini is not offered there ([pricing](https://tinker-docs.thinkingmachines.ai/tinker/models/models_and_pricing/index.md)).
- **Numerics caveat:** the docs say training and sampling may "use different numerics" and "low precision numerics" ([StableReinforce](https://tinker-docs.thinkingmachines.ai/tinker/losses/stable-reinforce/index.md)). They also link nondeterminism in inference ([importance sampling](https://tinker-docs.thinkingmachines.ai/tinker/losses/importance-sampling/index.md)). There is no determinism guarantee for logprobs.
- [INFERENCE] Tinker top-k may differ slightly from a published-checkpoint reference, so record the backend in the pack.

## 3. Tinker model cadence, bring-your-own weights, account
- **Cadence:** the Qwen3.8-27B HF repo was created on 2026-08-05 ([HF API](https://huggingface.co/api/models/Qwen/Qwen3.8-27B)). Cookbook renderers for it shipped in v0.5.5 on 2026-08-21 ([changelog](https://tinker-docs.thinkingmachines.ai/llms-full.txt)). The Inkling 2 Mini card points to Tinker at release ([card](https://huggingface.co/thinkingmachines/Inkling-2-Mini)). Models are also retired, for example Qwen3.6-27B on 2026-10-23 ([deprecations](https://tinker-docs.thinkingmachines.ai/tinker/model-deprecations/index.md)). Tinker says: "Avoid building hard dependencies on any specific model". [INFERENCE] New releases can appear within weeks, but any given Source can disappear.
- **Arbitrary HF checkpoint:** no. You can only use listed base models; the docs offer a model-request form. External weight upload must be "exactly what `save_weights_external` exports for `base_model` and `lora_config`" ([RestClient](https://github.com/thinking-machines-lab/tinker/blob/3e952a8b979654cacc9dc68aadeb50bc418036a7/src/tinker/lib/public_interfaces/rest_client.py#L510)), so it only covers weights tied to a listed base model and LoRA config.
- **Account:** you need to sign in, get an API key and "set up payment info" ([quickstart](https://tinker-docs.thinkingmachines.ai/tinker/quickstart/index.md)). Billing is pay-per-token. A free tier is not documented.

## 4. vLLM
- **Prompt logprobs at 8K:** vLLM computes them in chunks of `CHUNK_SIZE = 1024` rows. It also caps the `topk` workspace, which it notes as "~5.5 GiB for 1024 rows at a 152k vocab" ([prompt_logprob.py](https://github.com/vllm-project/vllm/blob/f7db8ac0ebcded8dd1750687a86fc107a821beba/vllm/v1/worker/gpu/sample/prompt_logprob.py#L20-L23)). [INFERENCE] With a 248K vocab that is several GiB of transient memory per chunk, so leave headroom (for example via `gpu_memory_utilization`).
- **Past issues:** OOM with logprobs (tracking issue [#5907](https://github.com/vllm-project/vllm/issues/5907), [#5550](https://github.com/vllm-project/vllm/issues/5550)). Chunked prefill gave partial prompt-logprob output in [#14239](https://github.com/vllm-project/vllm/issues/14239), now closed. `prompt_logprobs` ≥10 broke in V1 0.8.3 ([#16836](https://github.com/vllm-project/vllm/issues/16836)). `max_logprobs` defaults to 20 ([config](https://github.com/vllm-project/vllm/blob/6aeedab553dd85d6bc3f9f4deb3bb264bce0cb7c/vllm/config/model.py#L305-L309)).
- **Inkling-2-Mini:** needs vLLM 0.35.0+ nightly, NVFP4 variant, minimum 24 GB VRAM. The recipe marks it verified on H100, H200, B300, GB200/GB300 and DGX Spark, and caps H100 at a 262K context ([recipe JSON](https://recipes.vllm.ai/thinkingmachines/Inkling-2-Mini.json)).
- **Qwen3.8-27B:** needs vLLM 0.17.0+. BF16 is 51.7 GiB of weights and needs about 67 GB VRAM on one GPU ([recipe JSON](https://recipes.vllm.ai/Qwen/Qwen3.8-27B.json)).

## 5. transformers
- Both models have official classes in release v5.24.0 (2026-11-21): `qwen3_5` and `inkling2_loop`. No `trust_remote_code` is needed ([v5.24.0 models](https://github.com/huggingface/transformers/tree/v5.24.0/src/transformers/models/inkling2_loop)).
- **Inkling NVFP4:** the doc says the checkpoint's "NVFP4 and MXFP8 quantized layers … Transformers dequantizes when loading" ([model doc](https://github.com/huggingface/transformers/blob/d8f10a82213a3a9db48385aba3a4b57ab535de50/docs/source/en/model_doc/inkling2_loop.md)). It runs on GPU in BF16 after dequantization, not with NVFP4 kernels. The NVFP4 quantizer rejects pre-quantized checkpoints ([quantizer_nvfp4.py L54](https://github.com/huggingface/transformers/blob/d8f10a82213a3a9db48385aba3a4b57ab535de50/src/transformers/quantizers/quantizer_nvfp4.py#L54)). [INFERENCE] Dequantized results won't exactly match vLLM's NVFP4 kernel output, and 26B params in BF16 is about 53 GB, which needs an 80 GB GPU.

## 6. GPU rental (list prices)
- RunPod H100 SXM 80 GB: $4.39/hr on Secure Cloud, from $2.69/hr on Community Cloud ([RunPod](https://www.runpod.io/pricing)).
- Lambda H100 SXM 80 GB: $4.69–$4.89/GPU/hr on its multi-GPU (2/4/8×) instances ([Lambda](https://lambda.ai/pricing)).
- One H100 80 GB covers both models: Inkling NVFP4 needs ≥24 GB and Qwen BF16 about 67 GB. [INFERENCE] A 24K-token run should take well under an hour, so roughly $3–5 per pack.
